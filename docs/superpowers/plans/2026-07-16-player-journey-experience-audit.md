# Player Journey Experience Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the highest-impact player-journey failures in the lobby and run scenes, make Android pause/back/touch behavior predictable, preserve rewards across retry, and add a repeatable real-scene audit that proves the complete home-to-run-to-result loop.

**Architecture:** Keep `MainMenuBootstrap`, `PenguinRunnerGame`, `RunnerGameController`, and `RunOutcomeRouter` as the existing orchestration and authority boundaries. Add four small pure helpers for modal ownership, launch idempotency, gesture thresholds, and per-attempt settlement. Extend the retained HUD with explicit pause actions, centralize run result capture/application, and reset presentation-only runtime state on retry. Add editor validators and a play-mode journey smoke runner that exercise the actual scenes and UI hierarchy rather than a duplicate test UI.

**Tech Stack:** Unity 6.0.4, C# 9, retained uGUI/TMP, Unity editor command-line tests, PowerShell contract gates, Android landscape build.

internal sealed class RunLaunchGate
