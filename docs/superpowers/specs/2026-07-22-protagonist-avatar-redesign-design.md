# 主角建模与 Avatar 系统重构设计

日期：2026-07-22  
状态：已确认设计，待实施计划

## 1. 背景与目标

当前主角咕咕嘎嘎由 `CutePenguinMesh` 生成程序化网格，再由 `PenguinCharacter` 追加配饰、动画偏移和反馈特效。该方案能够稳定运行，但模型品质、动作生命力和扩展边界已不足以支撑当前游戏的美术水准。

本次重构同时解决三类问题：

- 将主角升级为细节完整、轮廓鲜明的“敏捷跑酷英雄”。
- 用骨骼动画提升跑、跳、换道、滑铲和交互反馈的动作质量。
- 建立完整的数据驱动 Avatar 系统，使未来角色、皮肤、材质、动画集和配饰可以替换，而不修改玩法判定。

首版只制作咕咕嘎嘎默认形象，不同时制作额外皮肤或完整换装界面。现有程序化企鹅保留为资源加载失败时的安全回退。

## 2. 已确认的视觉方向

主角采用“敏捷跑酷英雄”方向：身体比现有形象略修长，重心前倾，翼尖更利落，脚掌加宽以强化落地和冲刺姿态。护目镜是第一识别符号，红围巾既延续现有 IP 特征，也用于强化运动轨迹。

材质采用风格化 PBR：

- 身体以哑光深蓝羽毛表面为主。
- 护目镜、扣件保留克制的高光。
- 围巾体现简化织物纹理和粗糙度差异。
- 镜片不使用昂贵的实时折射。
- 造型细节服务于横屏跑酷镜头下的轮廓识别，不追求只能在极近特写中看到的噪声。

“高模”指以高模雕刻建立可靠造型和表面细节，再将细节烘焙到实时游戏模型；超高面数雕刻体不得直接进入运行时资源。

## 3. 模型与资源规格

美术流程为：高模雕刻、低模重拓扑、UV、法线/AO/曲率烘焙、风格化 PBR 贴图、骨骼蒙皮、动画制作、Unity Prefab 与 LOD 配置。

建议运行时规格：

- LOD0：约 35k–50k 三角面，用于大厅展示和近距离演出。
- LOD1：约 20k 三角面，用于正常跑酷镜头。
- LOD2：约 7k 三角面，用于远景或较低质量档。
- 一套 2K 主图集，覆盖身体、腹部、眼睛、围巾、护目镜和扣件。
- 正常跑酷镜头下不超过约 3 个材质批次。
- 面数优先分配给脸部轮廓、翅膀变形、脚蹼、围巾和护目镜；腹部等平缓区域降低密度。

高模源文件与 Unity 运行时资源分开保存。`Assets/Resources` 只包含经过压缩、具有明确用途的运行时 FBX、贴图、材质、Avatar 配置和 Prefab。

骨架至少支持眼球、眼皮、喙、翅膀与翼尖、脚蹼、围巾链和配饰辅助骨。配饰插槽绑定明确骨骼引用，不依靠字符串猜测层级。

## 4. 数据驱动 Avatar 架构

### 4.1 配置资产

`RunnerAvatarDefinition` 是单个角色的总配置，引用模型 Prefab、动画集、外观集、插槽集、朝向、缩放、LOD 和表现参数。

`RunnerAnimationSet` 声明待机、跑步、左右换道、跳跃、下落、落地、滑铲、受伤、失败和庆祝动画，并提供同类别回退片段。

`RunnerAppearanceSet` 管理身体材质、镜片、围巾及其他默认外观，并定义未来皮肤的覆盖边界。首版仅包含默认外观。

`RunnerAccessorySocketSet` 声明头部、脸部、颈部、背部等稳定插槽。首版只绑定默认护目镜和围巾，但数据结构允许后续内容覆盖。

### 4.2 运行时组件

`PlayerAvatarPresenter` 是表现层入口。它从 `RunnerAvatarDefinition` 实例化模型，并协调动画、材质、配饰、表情、次级运动和反馈特效。

`RunnerAnimationDriver` 读取玩法层提供的只读状态并设置 Animator 参数。它不修改玩家坐标、速度、碰撞盒、伤害或奖励。

`RunnerExpressionDriver` 控制眨眼、视线、受伤、兴奋和眩晕表情，避免将短促面部变化塞入基础移动状态机。

`RunnerSecondaryMotion` 以移动端可控的程序化方式处理围巾摆动、护目镜轻震和落地回弹。该模块必须避免逐帧分配，并允许按质量档关闭或简化。

`RunnerCharacterFx` 承接现有护盾、冲刺、磁铁、无敌、跳跃环、滑铲轨迹、受伤和庆祝特效。特效仍由现有游戏事件触发。

### 4.3 玩法边界

模型和动画只替换视觉表现。以下规则保持独立且不得由动画驱动：

- `PlayerMotor` 的移动、速度与输入响应。
- `PlayerMotor.BodyHeight` 的站立、滑铲和起身判定。
- 玩家碰撞盒、障碍规避和 Boss 命中逻辑。
- 道具获取、伤害、奖励和结算。

关闭 Root Motion。步态速度通过动画播放速率或 Blend Tree 与实际速度匹配，而不是让动画推动角色。动画事件只可触发脚步声、落地尘、围巾甩点等表现事件。

## 5. 动画与交互设计

首版动画集包括待机、跑、左右换道、跳跃、下落、落地、滑铲、受伤、失败和庆祝。

动作要求：

- 跑步包含起跑蓄势、左右重心、翅膀反向摆动、脚掌压缩和头部稳定。
- 换道包含预倾、侧向发力和回正，并保持操作立即生效。
- 跳跃包含蹲身蓄力、腾空收脚、下落预备和落地压缩。
- 滑铲明确降低身体轮廓，围巾沿速度方向拖曳。
- 受伤表现轻微踉跄；失败使用完整倒地演出。
- 庆祝包含停步、回头、挥翼和恢复待机。

Animator 使用三层结构：

1. 基础层处理待机、跑、跳、下落、落地、滑铲和失败。
2. 动作叠加层处理换道倾斜、拾取、完美闪避、Boss 反击和道具激活。
3. 表情层处理眨眼、视线、受伤、兴奋和眩晕。

拾取鱼干、激活护盾、冲刺、磁铁吸附、完美闪避和 Boss 反击使用短促叠加反馈，不得阻断跳跃、滑铲等关键动作，也不得延迟输入响应。

## 6. 运行时数据流

`PlayerMotor`、道具系统和游戏事件总线输出只读状态，由 `PlayerAvatarPresenter` 汇总成统一的 `RunnerAvatarState`。该状态至少包含速度、横向移动量、垂直速度、是否落地、滑铲比例、受伤、失败、庆祝和当前增益状态。

`RunnerAnimationDriver` 将 `RunnerAvatarState` 转换为稳定的 Animator 参数；表情、次级运动和特效模块只消费各自需要的字段。模块之间不直接控制彼此，所有跨模块同步通过 Presenter 或明确的表现事件完成。

## 7. 错误处理与降级

- Avatar 配置完整时加载高品质模型、动画、材质、配饰和特效。
- 单个动画缺失时回退到同类别默认动作，并输出包含角色 ID 和片段名的警告。
- 配饰或材质缺失时隐藏对应插槽，不阻断开局。
- 新模型或核心配置无法加载时回退到现有程序化企鹅。
- Animator 参数不匹配时，编辑器验证失败；正式包跳过无效参数并维持基础跑步。
- LOD、贴图和次级运动按质量档选择。中档默认使用适合正常跑酷镜头的 LOD，近景展示允许使用 LOD0。

编辑器验证器在构建前检查必需动画、骨骼插槽、材质槽、朝向、缩放、LOD 阈值、碰撞参考尺寸和 Animator 参数。

## 8. 验证与验收

### 8.1 自动化验证

- `RunnerAvatarDefinition` 及其依赖资产的必需字段完整。
- Animator 参数、状态、Layer 权重和退出时间与动画集一致。
- FBX 导入设置正确，Root Motion 关闭，材质数量、贴图尺寸和 LOD 阈值在预算内。
- 模型替换前后碰撞盒与 `PlayerMotor.BodyHeight` 判定不变。
- 高品质模型加载失败时，程序化企鹅回退路径可用。
- 连续重试、暂停恢复、失败结算和返回大厅后不残留动画或特效状态。

### 8.2 动作验收

- 实际横屏跑酷镜头下，换道、跳跃、滑铲、受伤和失败姿态可快速辨认。
- 跑→跳→落地→跑、空中→滑铲、换道中受伤、冲刺中拾取等组合无明显跳帧、穿插或状态锁死。
- 交互动画与音效、粒子时点一致，但不改变玩法触发时机。

### 8.3 视觉与性能验收

- 输出正面、背面、侧面、跑、跳、滑铲、受伤、失败和庆祝截图。
- 在冰湖、海洋、天空等明暗差异明显的主题中检查材质、轮廓和镜片高光。
- Android 中档以 60 FPS 为目标；角色动画、表情和次级运动不产生逐帧 GC。
- LOD0 与 LOD1 切换时，脸部、护目镜和围巾轮廓不得出现明显跳变。

## 9. 首版范围外

- 额外皮肤和可切换角色内容。
- 面向玩家的帽子、护目镜、围巾和背部饰品换装界面。
- 动画驱动位移或对玩法判定的修改。
- 实时毛发、镜片折射、布料模拟等高成本效果。
- 对 Boss、伙伴或敌人角色系统的同步迁移。

## 10. 完成定义

当默认咕咕嘎嘎能够通过数据配置加载高品质骨骼模型，完整播放核心跑酷与交互动画，在现有玩法判定不变的前提下通过自动化、视觉和 Android 性能验收，并且资源缺失时能够回退到程序化企鹅，本次重构视为完成。
