# 《企鹅快跑》精品首页与全量地图资产升级设计

日期：2026-07-15
状态：视觉与技术方向已逐段确认，等待书面规格复核

## 1. 背景与目标

当前版本已经建立“童话营地”首页、纸张式功能面板、六主题跑酷地图，以及程序化障碍、道具和部分开放模型混用的视觉基础。本轮升级不改变核心跑酷规则，重点解决两个问题：

1. 首页虽然结构完整，但场景需要达到主视觉品质，让玩家打开游戏时首先感受到可居住、可成长的极地营地，而不是 UI 卡片或简化几何体。
2. 地图中的障碍、收集道具和环境陈设需要从“程序化几何体或通用模型换色”升级为具有独立轮廓、结构、材质和局部动态的正式资产。

本轮设计目标是：

- 首页采用“沉浸故事书”方向，布局像一张可操作的故事书跨页，中心仍是营地全景。
- 本轮页面实现优先打磨首页大厅，不同时重做任务、图鉴、营地和设置等子页面。
- 障碍、收集道具和环境陈设全部纳入美术升级，采用“手作故事雕塑”造型语言。
- 允许新增外部 FBX、Prefab 和贴图资源，并采用全量定制资产方案。
- Android 性能、玩法剪影和碰撞一致性优先于无约束的高面数与透明特效。

## 2. 已确认的设计决策

| 项目 | 决策 |
| --- | --- |
| 首页气质 | A：沉浸故事书 |
| 本轮页面范围 | C：先把首页大厅做到精品，再逐页推进 |
| 地图资产范围 | 障碍、收集道具、环境陈设三类全部重要 |
| 地图造型语言 | A：手作故事雕塑，要求细致建模 |
| 资源边界 | 允许新增外部模型与贴图 |
| 资产生产方式 | B：全量定制资产，不以换色复用主模型 |
| 首页布局 | 中央营地舞台、左侧今日手记、右侧下一章节、底部五枚书签入口 |
| 首页场景标准 | 使用正式营地全景与角色主视觉，包含建筑成长、角色互动和局部环境动态 |

## 3. 范围

### 3.1 本轮包含

- 精品首页大厅的场景与界面升级。
- 首页主角、伙伴、五处成长建筑和关键互动节点的正式视觉资产。
- 六张主题地图的全量资产目录、映射和验证架构。
- 54 个主题障碍预制体的生产目标：9 种玩法角色乘以 6 张地图。
- 18 个独立收集道具预制体。
- 48 个主题环境陈设：每张地图 8 个。
- 外部模型和贴图的统一导入、命名、材质、LOD、碰撞与回退标准。
- 六主题截图、玩法判定回归、移动端性能与 Android 构建验证。

### 3.2 本轮不包含

- 任务、图鉴、营地商店和设置页面的完整视觉重做。
- 新的跑酷输入、新障碍判定规则或新经济系统。
- 因美术升级而修改现有跳跃、滑铲、换道、拾取或受伤窗口。
- 为追求细节而取消低画质档、对象池或移动端资源预算。

### 3.3 分批交付

全量定制资产规模较大，按照以下顺序实现并逐批验收：

1. 资源目录、视觉目录和生成/验证工具。
2. 精品首页与 12 个营地主视觉资产。
3. 每张地图 3 个高频障碍，共 18 个首批主题障碍。
4. 六个高频收集物：鱼干、冲刺、磁铁、护盾、星星、滑翔。
5. 每张地图 1 个地标和 3 个高频陈设，共 24 个首批环境资产。
6. 补齐剩余 36 个障碍、12 个道具和 24 个环境陈设。

任一批次都必须可独立运行，并保留下一批资产缺失时的稳定回退。

## 4. 精品首页设计

### 4.1 视觉方向

首页是一幅可交互的极地营地全景，而不是通用游戏面板。整体使用水彩与手绘质感、温暖灯笼、雪地反光、旧纸张、木制书签和少量极光色作为状态反馈。极光玻璃不作为主要材料，仅用于资源提示、季节状态或稀有奖励。

场景需具备前、中、后景：

- 前景：雪堆、脚印、木箱、灯笼、绳索和可轻微摆动的近景物。
- 中景：主角、伙伴、营火、帐篷、五处成长建筑及其可交互热点。
- 后景：冰湖、栈桥、远山、树林、云层和极光或日落空气层。

### 4.2 信息层级

- 顶部状态条：玩家等级、鱼干、稀有资源和当前章节/季节，保持紧凑。
- 左侧纸页：只显示一条最高优先级的“今日手记”，包含简短叙事、进度和奖励。
- 右侧纸页：显示下一章节、主要危险、奖励倾向、难度和唯一主按钮“翻开旅程”。
- 底部书签：营地、任务、图鉴、伙伴、设置五个稳定入口。
- 中央场景：保持主角和营地可见，不叠加任务卡、营销弹窗或大段说明。

### 4.3 场景互动

- 主角位于中央可行动区域，使用呼吸、眨眼、挥手或查看地图等低频待机动作。
- 伙伴按存档与羁绊状态轮换出现，点击后进入对话或伙伴信息。
- 五处成长建筑根据等级替换外观层级，并通过灯光、旗帜、烟雾、工具或积雪变化表现成长。
- 热点只在可交互、可领取或可升级时增强，普通状态保持低干扰。
- 打开功能面板时暂停场景点击，返回后恢复；场景轻动画无需暂停。

### 4.4 响应式规则

- 基准为横屏 16:9。
- 较窄横屏优先缩小左右纸页宽度和正文行数，不缩小主按钮点击区域。
- 安全区内固定顶部资源条与底部书签，中央角色不得被裁切到失去面部和动作反馈。
- 左右纸页在极窄横屏可收为书签摘要，但首页主按钮始终可达。

## 5. 地图资产设计

### 5.1 共同造型语言

所有地图资产采用“手作故事雕塑”语言：低至中等面数作为基础，使用手刻切面、非完全对称轮廓、分层结构、可信连接件和手绘 PBR 材质形成细节。细致不等于无限增加面数，必须同时满足四个层级：

1. 玩法剪影：远距离能判断跳跃、滑铲、换道或反制方式。
2. 结构可信：支撑、绳结、木楔、裂纹、破损和受力方向有明确原因。
3. 主题故事：冰层气泡、木纹刀痕、铜锈、潮湿水线、珊瑚附着、帆布补丁各自独立。
4. 动态反馈：预警、擦肩、命中或拾取时只让关键部件响应。

### 5.2 六主题差异

| 地图 | 主材质 | 结构语言 | 局部动态 |
| --- | --- | --- | --- |
| 冰湖回音谷 | 透明冰、压雪、冻石 | 裂隙、音叉形冰柱、层叠冰板 | 裂纹发亮、冰屑、轻微反射闪动 |
| 雪松废墟 | 雪松木、旧绳、苔藓石 | 倒木、绳桥、木楔和手刻符号 | 绳索绷紧、木屑、旗布摆动 |
| 极光磁场 | 磁石、铜环、极光晶体 | 导体线圈、悬浮环和极性标记 | 能量弧、极性切换、细小悬浮 |
| 北境雾堤 | 湿石、锈铁、雾灯玻璃 | 水闸、堤坝、管线和防洪支撑 | 雾灯摇晃、水滴、阀门震动 |
| 海洋珊瑚礁 | 珊瑚、贝壳、湿木、气泡 | 珊瑚分叉、贝壳护板和漂流残骸 | 气泡、软体摆动、水光掠过 |
| 天空飞翔 | 浮木、帆布、羽毛、云晶 | 风帆、气囊、浮桥和风向标 | 帆布鼓动、羽毛流线、云雾拖尾 |

同一玩法类型在六张地图中保持碰撞和安全高度一致，但主轮廓与结构必须独立。例如滑铲门可以分别表现为冰拱、倒木梁、磁环、雾堤水闸、珊瑚弓和浮空帆架。

### 5.3 障碍资产

障碍覆盖以下九种玩法角色：

- 高障碍 `StandardHigh`
- 滑铲门 `SlideGate`
- 宽滑铲门 `WideSlideGate`
- 宽墙 `WideWall`
- 敌人 `Enemy`
- 滚动物 `Rolling`
- 中型障碍 `MediumBarrier`
- 高尖刺 `TallSpike`
- 飞行障碍 `Flying`

每个玩法角色在六主题中拥有独立 Prefab，总计 54 个。视觉网格不得直接作为碰撞网格；继续使用现有 `ObstacleColliderSpec`，并通过预览工具叠加显示真实碰撞体和推荐规避方式。

### 5.4 道具资产

18 个道具全部拥有独立剪影和中心符号。通用道具不因进入不同地图而失去识别，但可以添加低成本的主题挂件或粒子。道具视觉由三层组成：

- 实体核心：护符、器具、羽毛、沙漏、鱼形装置等正式模型。
- 识别环：统一尺寸与高度的低透明度环形反馈。
- 状态特效：拾取前低频旋转或呼吸，拾取时短促爆发。

道具不能只用球体、圆环和发光颜色区分。

### 5.5 环境陈设

每个主题至少包含 8 个独立陈设：地标、路标、植物或生物、灯具、残骸、边缘结构、地面小物和远景轮廓。陈设只放置在不遮挡三车道预读的位置。高频重复物使用实例化和主题图集，地标拥有独立 LOD 和远景替身。

## 6. 资源与运行时架构

### 6.1 目录与导入

建议目录：

```text
Assets/Art/PenguinRun/
  Home/
  Obstacles/<Theme>/<ObstacleKind>/
  Pickups/<PowerUpKind>/
  Environment/<Theme>/<PropId>/
  Shared/Materials/
  Shared/Textures/

Assets/Resources/PenguinRun/VisualCatalogs/
Assets/Resources/PenguinRun/Prefabs/
```

源模型统一使用 FBX；运行时引用 Unity Prefab。每个主题使用共享材质图集，但每个物件拥有独立绘制区域，不以纯色 Tint 代替主题材质。导入规则统一缩放、法线、切线、压缩、读写权限和动画设置。

### 6.2 视觉目录

新增 `RunnerVisualAssetCatalog`，以稳定键映射资产：

- 障碍键：`RunnerMapTheme + ObstacleKind`
- 道具键：`PowerUpKind`
- 环境键：`RunnerMapTheme + EnvironmentPropId`
- 首页键：`CampNodeId + UpgradeLevel`

每条记录包含 Prefab、局部缩放、朝向、位置偏移、LOD 策略、阴影策略、特效挂点和回退键。

### 6.3 运行时职责

- `SegmentSpawner` 继续决定生成时机、车道、距离、碰撞规格和对象池生命周期。
- 新增 `RunnerVisualFactory`，从视觉目录解析并实例化外观，不参与玩法判定。
- 外观对象挂到现有玩法根节点下，碰撞和标记组件保留在根节点。
- 首页由场景编排器管理营地节点，由故事书视图管理 uGUI；两者通过只读首页视图模型同步。
- 资源缓存按稳定键工作，避免在跑酷过程中重复 `Resources.Load`。

### 6.4 回退与错误处理

解析顺序为：

1. 精确主题资产。
2. 同玩法类型的通用精细资产。
3. 当前程序化网格。

缺失资产、材质丢失、异常包围盒、LOD 空引用和重复键只记录一次结构化日志。任一视觉资产失败都不能生成空障碍或改变碰撞。首页节点失败时保留正式全景和纸页 UI，不阻塞开始游戏。

## 7. 性能标准

- 以中档 Android 设备稳定帧率为目标，先记录现有基线，再锁定可见三角面、Draw Call、粒子和透明层预算。
- 障碍和地标至少提供 LOD0、LOD1 与远景替身；小型道具根据屏幕尺寸使用 LOD 或单一轻量网格。
- 高频环境物使用 GPU Instancing；动态角色、透明材质和粒子不盲目合批。
- 主题材质优先使用图集，避免每个小物拥有独立材质实例。
- 低画质档关闭次级粒子、透明叠层、远景动态和高成本阴影，但保留玩法剪影、预警和拾取反馈。
- 主线程不得在高压跑酷片段同步加载未缓存模型。

## 8. 验证与验收

### 8.1 自动检查

- 校验 54 个障碍、18 个道具和 48 个环境陈设的目录、稳定键、Prefab、材质和 LOD 完整性。
- 校验每个障碍视觉的包围盒与 `ObstacleColliderSpec` 没有造成误导性高度或宽度。
- 校验资源目录无重复键，所有回退键可解析。
- 保持现有 UI、阶段一、阶段二和阶段三静态门禁通过。
- 执行 Unity C# 编译、资源导入检查、Android 构建和 `git diff --check`。

### 8.2 视觉检查

- 首页至少截取默认、可领取、可重建、面板打开和窄横屏五种状态。
- 六张地图分别截取正常跑酷、障碍密集、奖励段和低画质画面。
- 检查障碍在首次进入预读距离时能否判断规避动作。
- 检查道具在不同主题背景上是否仍能通过轮廓而非颜色识别。
- 检查环境陈设不遮挡三车道中心和下半屏操作区。

### 8.3 玩法回归

- 验证跳跃、滑铲、换道、拾取、受伤和擦肩判定在换模前后一致。
- 验证对象池复用时不残留旧主题材质、粒子和动画状态。
- 验证缺失精确资产时依次回退，不出现空模型、空引用或生成中断。
- 验证暂停、结算和返回营地后首页热点与场景输入恢复正确。

### 8.4 完成定义

只有在对应批次的资产覆盖检查、Unity 编译、Android 构建、运行时截图、玩法判定和性能记录均有新鲜证据时，才能声明该批次完成。若 Unity 许可证、设备或外部资产服务阻塞运行验证，必须报告具体阻塞和未验证项目，不以静态检查代替。

## 9. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 全量资产数量大，单次交付失控 | 按首页、高频障碍、高频道具、高频陈设、补齐目录分批验收 |
| 精细模型降低移动端帧率 | 先采集基线，强制 LOD、实例化、图集和质量档 |
| 外观与碰撞不一致 | 碰撞独立于视觉网格，并提供包围盒叠加验证 |
| 六主题仍像换色 | 每主题定义独立主材质、结构语言和局部动态；禁止只改 Tint |
| 外部资产风格不统一 | 统一比例、手绘 PBR、轮廓、磨损和导入规范，再进入运行时目录 |
| 首页场景过于丰富导致信息拥挤 | 丰富度集中在场景，UI 只保留两张纸页、顶部状态和底部书签 |

## 10. 后续工作

书面规格确认后，下一步编写分阶段实施计划。实施计划必须先建立资源目录和视觉目录，再落地首页和首批地图资产；不得直接在 `SegmentSpawner` 中继续追加大段建模分支。
