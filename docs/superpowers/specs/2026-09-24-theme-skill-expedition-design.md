# 主题技巧远征：冰湖与雪松样板设计

状态：用户已同意“冰湖＋雪松样板”方向；本文是待书面复核的设计规格，尚未实施。

## 1. 目标与范围

让路线选择产生可辨认的实际操作差异：冰湖冒险线强调跳跃与空中收集，雪松冒险线强调滑铲节拍；稳健线提供明确的低压补给。场景、路线提示、技巧反馈与现有局内成长共同服务这段体验。

本批不是新增游戏模式，也不增加主题数量。只深化 IceLakeEcho 和 CedarRuins 两张现有地图的两个既有事件，保留其余四主题及其他事件的行为。用户已确认此方案优先于纯美术精修和大规模系统扩展。

不做：章节叙事、高松鹅终章、角色换装、联网、排行榜服务、新货币、新永久成长层、新操作手势、新道具种类或主角网格重建。不得把构图草案的 CSS 角色和几何图形当作生产美术资源。

## 2. 已核实的起点

- RouteEventCatalog 已有冰湖 ice-fracture（风险分岔，冒险结果为 JumpArc）和雪松 cedar-rescue（伙伴救援，冒险结果为 SlideTunnel）。事件 ID 同时服务发现记录，必须保留。
- RouteEventDirector 首次事件距离为 220m，最小事件间距为 280m，选择窗口为 72m；本批不调整这些常量及现有抽取种子规则，不额外保证每局一定先遇到样板事件。
- SegmentSpawner.TryConsumeRouteChoice 在玩家越过决策线时按车道作选择：右道冒险，左道及中道稳健；超时也回落稳健。草图中可点击的路线卡只用于预览，正式游戏不增加点击选路输入。
- SegmentSpawner.SpawnRouteEventOutcome 当前生成不同形状的引导条，并对 FishRibbon、CalmLane、JumpArc 部分生成鱼干；该函数没有生成与 JumpArc / SlideTunnel 对应的真实障碍。这是本批优先补齐的玩法缺口。
- SkillScoreTracker 已支持完美闪避、空中收集、冒险路线和 Boss 反击；连段窗口 2.5 秒，上限倍率 3 倍。本批不新增第二套连段或记分权威。
- RunUpgradeCatalog 已有羽毛跃步、闪避喝彩、鱼干挎包、前路侦察、反击信号等强化。保留其当前效果及抽取规则，不重复发放路线或技巧奖励。
- 既有工作区包含输入暂停、碰撞公平和片段多样性修复；这些未提交改动属于当前基线，不得覆盖或顺带提交。

## 3. 两个可玩样板

| 项目 | 冰湖回音谷 | 雪松废墟 |
| --- | --- | --- |
| 既有事件 | ice-fracture / 冰镜分岔 | cedar-rescue / 雪松呼救 |
| 稳健选择 | 沿岸稳行：清楚的低压鱼干补给线 | 清理近路：开阔通路与低压补给 |
| 冒险选择 | 穿越裂冰：三次分离的跳跃机会，鱼干弧线对应可达跳跃轨迹 | 深入根廊：三次分离的滑铲机会，门廊轮廓清楚显示通行净空 |
| 操作语义 | 沿用跳跃、换道与空中收集 | 沿用滑铲、换道与起身宽容 |
| 视觉身份 | 冷青冰面、暖金鱼干、薄冰边缘与冰拱地标 | 暖色木构、冷色松影、分段门廊与石灯地标 |

### 3.1 遭遇节拍与可避让性

路线内部采用“入口识别 → 三个操作机会 → 出口留白”的短段结构，不再只有一条颜色不同的引导线。三个障碍不得铺满三道；玩家始终可以换道退出挑战，不要求一次连续完美操作才能活下来。

首个危险位置不得比既有生成安全距离更近。跳跃障碍复用 SmallJumpable 规格，滑铲门复用 LowSlideGate 规格，不改变净空、判定盒、动作窗口、滑铲结束起身语义或输入阈值。操作间隔复用对应既有模式的节拍，并以不同速度及现有强化状态验证可完成性；不为追求连段效果缩短现行反应预算。

规划路线起点时必须避开已生成内容，保留入口过渡带。路线占用的纵向区间不允许普通随机波次或主题机关再次生成重叠危险；离开占用区间后恢复正常片段消费。禁止通过清空玩家眼前已有障碍来制造空档。

连段来自真实动作和收集。普通成功通过不保证获得“完美”判定；受伤、错失和连段失效按既有规则处理。不把选择冒险直接展示为“完美通关”。

### 3.2 奖励与局内强化

保留事件目录中的原有选择奖励和结算时点；本文不重做“选择奖励”经济。实际鱼干只通过 PickupSystem 收集，真实技巧只通过既有 AwardSkill / SkillScoreTracker 链路计分，出口不再额外复制一次奖励。

冒险线既有鱼干数量不得因装饰引导点变多而自动增长。冰湖优先调整已有鱼干线的轨迹；雪松稳健线复用已有补给生成方式。若需要改变实际拾取数量，必须作为独立平衡变更说明，而不是美术改动的副作用。

保留现有三选一强化时机和候选池。玩家已拥有的羽毛跃步、闪避喝彩或鱼干挎包自然作用于对应玩法，不新增强制选择弹窗、不保证掉落指定强化、不把本局强化写入永久存档。

Boss 仍按原有遭遇条件自然到来，不在每段路线末尾强制刷 Boss。通过已有技巧得分与反击信号强化衔接反击高光，不修改 Boss 前摇、预警、血量或命中规则。

## 4. 美术与 HUD

### 4.1 场景层次

保持横屏 16:9、现有机位和 FOV。两主题各以一个清楚的路边地标组织远景，再用已有自然模型衔接中景，近场让位给三车道和障碍轮廓。不以增加全屏 Bloom、雾密度或大量粒子代替材质与明暗层次。

侧向纯装饰遵守 SceneryMinAbsX = 8.5m；中景约 13–16m，剥除碰撞并继续跟随弯道。路面扁平细节随瓦片生命周期销毁，不注册为玩法障碍。路线滑铲门是实际障碍，不能混作无碰撞背景门廊。

优先复用已入库且有授权记录的冰岩、木构、松树、石灯等资源；缺失时跳过可选装饰并保留既有障碍的可读外观，不用大方块或其他角色立绘充当正式替代品。共享材质染色走 MaterialPropertyBlock。此批不默认下载新素材或调用生图；后续若确需 gpt-image-2，遵守用户配置的专用 image2 CLI 通道。

### 4.2 选路与反馈

既有选路提示补充简短的“跳跃线 / 滑铲线 / 稳健补给”操作预期，保留真实事件标题。稳健与冒险同时使用文字、方向和轮廓区分，不能只靠绿色与红色。

提示只在选路窗口存在，锁定选择后收束；不在中央持续叠加路线名、机关文本和连段大字。中央短反馈只显示真实触发结果，不以逐帧刷新的倒计时抢占跑道。

沿用 RunnerHudFrostPalette。生命、暂停和 DashReady 保持可达；手动冲刺冷却只在 DashReady 显示。Boss 模式隐藏常规资源统计，保留生命、冲刺、Boss 血量、招式与反击提示。保留安全区适配；不把草图的窄窗口展示解释为支持竖屏游戏。

反馈继续通过 RunFeedbackKind / RunFeedbackProfile 分发。优先复用现有完美闪避、收集和反击配方，控制短促闪光与音效，不新增判定层直接振动、直接闪屏或 IMGUI 绘制。

## 5. 代码边界与数据流

既有权威链保持：RouteEventDirector 选中定义并解析选择 → RunnerGameController 应用既有结果 → 路线内容规划 → SegmentSpawner 生成注册实体 → CollisionSystem / PickupSystem 产生真实事件 → 既有技巧、强化和结算消费者更新。

预计新增小型纯数据规划模块 ThemeRouteEncounterCatalog，输入为当前主题、真实事件 ID、是否冒险及已有结果模式，输出为有界的障碍/鱼干/留白描述。只匹配上述两个事件；其他主题、其他事件与未识别组合返回“无定制”，继续使用现有路径。规划模块不读 PlayerSave、不碰 Unity 场景对象、不发奖励。

路线实体生成与清理放入 SegmentSpawner 的专用 partial 文件（拟名 SegmentSpawner.RouteEncounters.cs），共享现有注册、地形与资源回收入口，不复制碰撞算法。把主文件原有路线相关实现原样移入相邻 partial 后再扩展，并相应下调文件尺寸上限，禁止上调上限绕过门禁。

主控制器只传递既有选择结果和必要的生命周期信号。路线占用状态作为会话状态维护，HUD 只读快照；不把新路线状态塞进存档，不为两条样板新建全局管理器或独立任务系统。

## 6. 抑制、冲突与清理

- 新手期：保持整局抑制路线与主题机关，保留四种基础片段轮转，不出现两条定制路线。
- 暂停、教学等待、切后台：不推进路线计时、位移或生成；继续沿用上一轮统一输入清理语义，不恢复旧动作。
- Boss 活跃、前奏占用及主题切换：不启动定制路线。尚未显示给玩家的路线请求可直接取消；不越过优先级强行插入。
- Boss 或主题切换中断已生成路线：通过现有登记/清理机制释放其实体与占用状态，不让路线残留在新主题或 Boss 预警带，不因取消重复结算选择奖励。
- 主题机关与路线互斥：既有机关取消规则继续生效，定制路线的占用期也纳入互斥；结束后才能恢复调度，避免只有选路窗口互斥而结果段叠加危险。
- 死亡、重开、返回营地：清空路线对象、占用范围和短反馈；新局状态不能继承上一局选择。
- 未识别事件、缺失可选美术、非法规划：回退既有路线表现与已验证生成路径，不制造不可见障碍、不奖励第二次、不抛空引用打断游戏。
- Daily：保留现有种子语义；定制规划对同一输入确定，不额外使用随机数或宣称本批解决跨玩家每日同种子问题。

## 7. 验收标准

### 可独立运行的行为测试

1. 两个目标事件的稳健/冒险分支均有确定输出；其他事件与四张非目标主题走旧路径。
2. 冒险线各有三次匹配规格的真实操作机会；障碍与可拾取鱼干不是仅有 Renderer 的装饰。
3. 第一危险点、动作间距与出口留白满足现有安全预算；至少一条逃生车道保持可用。
4. 普通波次和主题机关不侵入已预留区间；路线结束或取消后调度恢复，不会永久停刷。
5. 选择解析、基础奖励、技巧分与强化增益各结算一次；取消、重复轮询和重开不能刷奖励。
6. 新手抑制、暂停冻结、Boss 优先级、主题切换和返回营地清理均有回归用例。

### 项目级检查

- 先新增并运行路线行为回归，确认旧实现缺少真实遭遇内容的失败，再实现至通过。
- 重跑 tools/TestGameplayFairness.ps1 与 tools/TestRunnerInput.ps1，保留前两批修复。
- 运行 tools/Verify*.ps1 全部门禁及 tools/CompileFullRoslyn.ps1；不得因本批放宽碰撞、公平性、资源或文件尺寸规则。
- 检查所有新增 C# 文件的 Unity .meta 配对、资源路径、空引用处理和本批 diff 空白错误。

### Unity 与设备验收

Unity 能运行时，对冰湖/雪松的入口、操作段、出口及 Boss HUD 拍实际机位截图；检查三车道、主角背面、鱼干轨迹、门廊净空和文字遮挡。至少覆盖 1920×1080 与超宽屏安全区，分别检查 Low/Medium/High。

Android 目标仍为现有 60fps 预算。实测两条路线的最坏帧、Draw Call、粒子和对象回收，与同机同档旧版本对比；不得声称仅凭桌面编译就完成了性能验收。低画质不能隐藏危险预警或操作引导。

历史任务记录过 Unity 许可证失败；执行时重新检查环境，若仍阻塞，明确区分“代码/独立回归已验证”和“Unity 画面/Android 实机待验证”。不修改许可证设置或用户存档来绕过阻塞。

## 8. 交付与评审

按依赖分为三部分：路线规划与生命周期、真实障碍与拾取内容、表现收口与全量回归。每部分可单独验收，但只有两主题端到端链路均完成才称为本批实现完成。

当前只交付本文，未宣称上述功能已实现。书面确认后再使用 writing-plans 编写含准确文件、失败用例、实现步骤和验证命令的实施计划。
