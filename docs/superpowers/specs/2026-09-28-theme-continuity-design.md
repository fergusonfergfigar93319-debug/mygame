# 主题一致性与切换安全设计

日期：2026-09-28；状态更新：2026-10-01。用户已以“开始”批准实施，M2a/M2b 已接入工作区代码并通过独立逻辑/编译检查。本文第 2 节保留设计前基线；当前交付证据见 `docs/VERIFICATION.md`，Unity/Android 仍待验收。

## 1. 玩家体验与范围

玩家进入雪松后，应遇到雪松路线、雪松机关与按雪松上下文选出的 Boss；完成的主题技巧应记入雪松精通。主题时间到点时，先让眼前的挑战与奖励段结束，再换景。暂停或长时间 Boss 战不能导致恢复后连续换图。

本规格拆成两个依赖明确的交付：M2a 统一当前主题与进度归属；M2b 让切换等待安全边界。继续服务 ADR-0005 的游玩内容与操作体验。保留六主题、既有操作、52 s 主题请求周期、碰撞与奖励规则、新手整局保护，不增加强制 Boss、剧情、货币、联网或资产。

轻松难度首 Boss 调整是后续 M2c 独立平衡实验，本文不把候选距离写入生产代码。G6 的消费掉级也独立处理，不混入本次跨主题结算。

## 2. 核实到的现状

| 路径 | 当前行为 | 玩家影响 |
| --- | --- | --- |
| `PenguinRunnerGame.ApplyRuntimeThemeChange` | 更新 currentTheme、NextRunTheme、地形、表现和 spawner | 场景与普通片段切换了 |
| `RouteEventDirector` 构造函数 | pool 与 seed 由开局主题确定，pool 为 readonly | 换景后继续出旧主题事件 |
| `SegmentSpawner.ApplyTheme` | 更新 waveDirector 与 routeTheme | 路线规划按新主题匹配旧事件 ID，冰湖/雪松定制计划可能退回普通表现 |
| `RunnerGameController.TryStartThemeMechanic` | context 使用 config.MapTheme | 主题机关仍属于开局主题 |
| `BossSystem.BuildSpawnContext` / `SpawnBoss` | 候选与主题特性读取 config.MapTheme | 场景与 Boss 选取上下文/特性可能不同 |
| `ThemeMasteryTracker` / `CaptureResult` | 一个绑定开局主题的 tracker，一个结算快照 | 不能正确表达一局多个主题的技巧进度 |
| `TryStartThemeTransition` | 仅检查运行状态、BossActive 与绝对时间；截止时间 +=52 | 可取消正在体验的路线，越过前奏/奖励段；长战斗后可能补切 |
| Daily | 开局主题按日期确定，但自动切换入口没有 Daily 判断 | “每日固定主题”并未端到端成立 |

这些是源代码路径发现，尚未以 Unity 录屏复现。`ThemeMasteryStore.ApplyRun` 已跨局累计事件与星级；不能把“多主题归属缺失”误诊为“精通完全不累计”。

## 3. 方案比较

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| A：只改轻松首 Boss 距离 | 变更小，首个高潮更早 | 无法解决画面、玩法和精通不同步，也无法保护路线出口 |
| B：统一主题，再加安全切换（推荐） | 六主题内容能正确出现和归属；保留现有节奏基础 | 需完善局内主题状态和多主题结算，范围可分为 M2a/M2b |
| C：每主题固定开场→机关→路线→Boss | 主题结构强 | 同时改 Boss 密度、奖励速度、新手压力和长局长度；当前缺少实机证据，不适合作为第一步 |

采用已批准的 B 方案。A 的距离调优后续单独试验；C 暂不实施。

## 4. M2a：主题的唯一归属

### 4.1 开局配置与当前主题分开

`RunnerSessionConfig.MapTheme` 保留为开局主题快照。controller 增加只读 CurrentTheme，成为本局玩法主题唯一权威；表现读取该值。`RunSession.NextRunTheme` 保留既有下一局选择行为，但不能作为当前玩法状态的读取入口。

controller 的主题应用入口负责在过渡遮罩内完成同一次提交：取消旧主题短期对象 → 切换当前主题 → 通知路线池、片段池、机关上下文、Boss 待选上下文和精通 HUD → 表现更新地形/场景/听感 → 安全播种。应用相同主题应无副作用，不重置计数、不多发奖励。

不重建整个 controller，不修改难度、开局新手快照、当前距离、分数、生命、札记层数或输入阈值。将新增协调逻辑放在小模块/partial，按现有文件行数门禁下调主文件上限。

### 4.2 各消费者的保留规则

| 消费者 | 随主题改变 | 必须保留 |
| --- | --- | --- |
| 普通片段 | 当前主题池、调色板；沿用 SetTheme | 新手四模式轮转约束、生成安全预算 |
| 路线 | 候选池与定制匹配主题 | 全局 CompletedCount、RiskyCompletedCount、已完成 ID、札记 1/3/5…触发语义、下一次允许距离 |
| 机关 | 新请求的 Theme | 整局最大次数、标志事件上限、冷却拍数、PressureDebt/RewardDebt、随机流 |
| Boss | 尚未预告的候选上下文、之后生成的主题特性 | 本局击败数/ID、下一只触发距离、难度、奖励去重；已预告定义不得重抽 |
| 精通 | 当前主题 HUD 与事件记录目标 | 每个主题本局累计，离开再返回不丢失 |

路线事件的随机策略要显式确定：维持现有开局 run seed 的构造规则，不在切图时再次读取 TotalRuns；各主题维护自己的事件序号，以该主题、开局 daily/runCount 和主题内序号使用既有排名算法。同样开局输入与主题访问序列得到同样事件序列；不宣称解决 Daily 跨玩家公平种子问题。取消已经展示的选择沿用 Cancel，不按 Expire 自动发稳健奖励。重复切图不把 nextEventDistance 重置为 220 m。

Boss 预告缓存仅在未进入前奏且主题确实改变时失效。已有前奏通过 M2b 阻止切图；预告谁就出场谁。没有符合主题的解锁 Boss 时沿用目录兜底，不为满足主题一致性跳过生涯/本局条件。

### 4.3 多主题精通与唯一结算

本局维护最多六个 tracker，首次访问主题时按现有 theme/mode/runSeed 初始化；重访复用。机关操作、伤害及共鸣只记录到当前主题。非当前主题冻结临时计时；离开时取消未完成机关，清空该主题的临时共鸣值/计时与连胜，保留已完成数量、最佳连胜、标志事件、契约进度和教学记录。取消不能算成功。

本提案将契约明确为“每个访问主题一个”：HUD 只显示当前主题契约，同主题重访不重抽、不重复完成；各主题契约仍至多结算一次。SkillBeforeDistance 仍使用全局 800 m 截止，但读取该主题活动期间赚取的技巧分，不能把旧主题分数计入新主题；在 800 m 之后首次访问该主题时，候选池排除该契约，以固定的主题种子从其他可用契约确定选择。此处是明确的拟议规则变更，需要行为测试，不能只替换 config.MapTheme 后沿用旧的全局技巧总分。

结果模型扩展为不可变的按主题快照集合，每主题最多一条；旧单主题结果适配成一条集合。存档继续使用现有 `theme_mastery_v1_<theme>_*` 键，不改变星级门槛。通过 `RunOutcomeRouter` → `GrowthTransaction` 的既有唯一结算边界逐主题合并；旧单快照入口和新集合入口不能双写。

局内切图不写存档，不调用结算。死亡/返回营地仍由既有终局入口结算一次，重开清空六主题临时状态。图鉴、羁绊与建筑等其他消费者仍按原本整局规则计算一次，不因遍历精通集合重复发放奖励。结算视图只对有有效进度的主题显示一行增量，不能继续把所有精通成果画成开局主题；不改普通资源、得分和重开按钮布局。

## 5. M2b：52 秒是切换请求，不是打断命令

### 5.1 单个待切请求与计时

每次新主题完成进入后，累计 52 s 有效 Running 时间；暂停、教学等待、札记选择和主题过渡不计时。Boss 战也不消耗主题轮换计时。达到门槛仅置一个 Pending 标记，不能排多次切图。完成后从 0 重新计时，不对旧绝对截止时间连续 +=52。

Daily 整局使用日期确定的开局主题，不积累切换请求。普通模式保留冰湖→雪松→极光→雾堤→海洋→天空顺序；玩家选择其他主题时从所选主题开始。

### 5.2 安全边界与优先级

| 状态/内容 | Pending 后的处理 |
| --- | --- |
| 死亡、退出、重开 | 丢弃请求，走既有清理，不提交下一主题 |
| 暂停、教学等待、札记弹层 | 冻结；返回 Running 后再判断 |
| Boss 距离 ≤180 m、已有前奏或 BossActive | Boss 优先；继续等待直到战后拾取窗口结束 |
| 已展示路线选择或 RouteEncounterActive | 允许正常完成，等其预约尾部通过既有回收线；不删掉眼前障碍加速换景 |
| 机关非终态 | 等预警、Active、Resolve/奖励全部结束；已有异常取消沿用原流程 |
| 战后奖励实体仍在前方 | 等这一批已生成拾取物全部被收集或经过正常回收线 |
| 以上占用均无，Running 且仍 Pending | 开始既有淡出/遮罩/淡入，只提交一次主题 |

Pending 后停止接受新的路线、机关和随机世界事件，不追加新的内容占用；已存在内容正常消耗。普通波次可继续跑到开始过渡时，保持现有安全播种/清场规则。Boss 调度保持距离权威，不能为等待换景改变其预警或攻击预算。

战后窗口用本批实体的拥有权/最远剩余 Z 表达，结束于全部收集或尾部回收；暂停时距离不动。不能用猜测的固定 2 秒替代，不能另发一次鱼干奖励。若没有实际生成奖励物，则立即释放，不形成永久等待。

正常等待的上限由当前有限路线/机关/奖励尾部决定；Boss 战不设强制切图超时。缺失对象沿现有注销路径释放占用。不得为满足固定时限强行隐藏危险、截断前奏或删掉未过身的奖励。

### 5.3 表现

沿用现有主题幕布、短主题名与听感切换，不新增常驻倒计时或中央排队提示。切图期间输入清理、生命/暂停可达性、16:9 与超宽安全区仍走既有路径。HUD 的路线标题、机关和精通在提交后来自同一个 CurrentTheme。

## 6. 后续 M2c 的量化依据

无道具基准使用 `v(d)=min(vmax,v0+kd)`，封顶前 `t=ln(1+kd/v0)/k`。下表是解析估算，不是实机结果。

| 难度/候选 | 起速 / 斜坡 / 上限 | 首 Boss 距离 | 预计有效运行时间 |
| --- | --- | --- | --- |
| 轻松现行 | 7 / .008 / 22 | 3600 m | 221.55 s |
| 轻松候选 A | 相同 | 1400 m | 119.44 s |
| 轻松候选 B | 相同 | 1800 m | 139.69 s |
| 普通现行 | 10 / .014 / 32 | 2200 m | 102.73 s |
| 困难现行 | 13 / .020 / 40 | 1600 m | 62.45 s |
| 专家现行 | 16 / .027 / 52 | 1300 m | 43.01 s |

后续优先对照 A/B：A 更接近两分钟高潮；B 给学习更多留白。两者在无道具基准下仍晚于普通。一次实验只改轻松首 Boss 触发距离及准确描述，不同时改后续间隔、血量、技能预警、伤害或奖励。必须单独观察新手与已毕业玩家；记录有效运行时间、墙钟时间、冲刺占比、Boss 到达率、首招受击率、首战胜率，不能用存活样本的平均值代替整体到达率。

## 7. 验收矩阵

| 层级 | 必须证明 |
| --- | --- |
| 纯逻辑 | 冰湖→雪松时路线池、机关请求、Boss 待选上下文一致；非法/重复主题请求无副作用 |
| 跨主题累计 | A→B→A 保留路线全局计数、主题内随机序号、札记层数、机关整局上限与精通进度 |
| 契约 | 技巧分按发生主题归属；晚于 800 m 的首次进入不抽已过期契约；重访不重抽或重复发奖 |
| Boss 缓存 | 未预告可换上下文；已预告阻止切图；前奏定义与出场完全相同 |
| 时间 | 51.9 s 未 Pending，跨过 52 s 仅一个请求；暂停/教学/弹层冻结；长 Boss 后不补切 |
| 路线 | 稳健/冒险选择、三个动作机会及出口完整；Pending 后不追加新路线，最后一段离开可继续切图 |
| 机关/奖励 | 机关结算一次、取消无成功奖励；战后奖励收集或回收前不切；空奖励不阻塞 |
| 每日/新手 | Daily 六种开局主题均不自动轮换；新手整局抑制项与基础片段轮转不变 |
| 结算 | 多主题各写一次；旧单主题输入可用；重复终局仍由既有幂等门阻止；其他成长奖励不乘以主题数 |
| Unity | 真实 spawner、controller、HUD、音频在遮罩中同步；缺失可选美术不影响玩法提交；不留旧实体 |
| Android | 16:9/超宽、三档画质，长局/暂停/前后台/主题回访；60fps 与对象回收须设备测量 |

实施时先写针对真实生产逻辑的失败用例，再实现；保留路线、公平、输入三个现有行为回归。运行全部 Verify 与全量 Roslyn，区分独立测试、编辑器执行和设备证据。主题权威检查需要覆盖全部消费方，不能只搜一个 CurrentTheme 属性就视为通过。

现有文件行数失败（BossEncounter 超限）单独报告，不提高门禁上限掩盖。本轮设计没有运行 Unity，也没有复核许可证或 Android 连接状态；历史许可证 198 不能写成今日新测试结果。

## 8. 交付顺序与边界

1. M2a：当前主题、路线切池与不丢计数 → Boss/机关消费 → 多主题精通与一次结算 → 更新现状文档。
2. M2b：Pending 状态与有效时间 → 占用/战后拾取保护 → Daily 锁定 → 实际切图与恢复回归。
3. 两项运行验收通过后再排 M2c。M3 扩充四张主题样板依赖 M2a，避免内容已写却无法按场景触发。

此文是批准的规格；CurrentTheme、多主题结算和安全切换已接入代码。独立测试与 Roslyn 不代表 Unity/Android 运行验收，未验证的画面、玩法体验和性能仍保持待验状态。
