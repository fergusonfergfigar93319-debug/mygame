# 《企鹅快跑》童话营地全量升级设计

## 1. 目标与定位

本轮升级把《企鹅快跑》从功能齐全但视觉与系统连接感不足的跑酷原型，推进为一款具有明确品牌气质、可重复游玩深度和长期成长反馈的横屏 3D 单机跑酷游戏。

整体视觉采用“童话营地”方向：绘本式卡片、手工边框、温暖角色关系、逐步复苏的营地和清晰的章节故事。局内跑酷不照搬局外装饰，而使用更轻、更克制的 HUD，优先保护三车道、障碍、道具和 Boss 预警的可读性。

本轮全部包含以下三层升级，并按顺序连续交付：

1. 童话视觉基础：大厅、HUD、全局组件、面板和旅程结算统一。
2. 局内玩法深度：路线事件、轻构筑、技巧评分和六主题 Boss 深化。
3. 长期成长：营地重建、伙伴羁绊、图鉴发现和统一目标系统。

## 2. 范围与边界

### 2.1 本轮范围

- 重构大厅的信息层级和视觉表现。
- 建立可复用的童话绘本式 UI 组件与图标体系。
- 完善局内 HUD、Boss HUD、暂停、死亡与胜利结算。
- 增加路线事件、局内强化选择和技巧评分。
- 为六个主题补充差异化事件、Boss 机制和战利品。
- 建立营地重建、伙伴羁绊、图鉴发现与目标反馈闭环。
- 完善存档版本、降级策略、静态验证和运行时验收入口。

### 2.2 不在本轮范围

- 不迁移 URP，继续使用 Built-in Render Pipeline。
- 不引入账号、云存档、实时排行或其他联网服务。
- 不改变横屏 16:9 产品定位。
- 不推翻现有跑酷输入、三车道结构、碰撞规格和伤害主链路。
- 不以大量高成本角色骨骼动画作为交付前提；优先使用程序化动画、Tween、粒子和模块化低多边形造型。

## 3. 核心体验循环

玩家每局经历以下闭环：

1. 在营地首页查看当前故事目标、伙伴状态、资源和推荐行动。
2. 在出发准备页选择主题、难度、伙伴、补给和追踪任务。
3. 进入主题跑酷，处理路线选择、障碍节奏、道具组合和动态事件。
4. 进入 Boss、追逐或其他主题高潮，并在胜利后进入奖励段或主动撤离。
5. 通过旅程册式结算查看成绩、死因建议、任务进度、新发现和成长收益。
6. 回到营地修复建筑、提升伙伴羁绊、补全图鉴并解锁下一步内容。

设计原则是让每次跑酷都推进营地故事，让每次局外成长都为下一局增加新选择，而不是单纯提升数值。

## 4. 第一阶段：童话视觉基础

### 4.1 设计语言

- 主材质：暖纸张、厚涂色块、木质与布料纹理、少量冰晶高光。
- 轮廓：轻微不规则的圆角和手工边框，不使用难以维护的随机形变。
- 色彩：奶油纸色、松针绿、雾蓝为基础，珊瑚橙用于主要行动，莓紫用于 Boss 与危险高潮。
- 字体：中文正文保持高可读性；标题通过字号、字重、字距与底板营造绘本感，不依赖难以覆盖中文字形的装饰字体。
- 动效：卡片像翻页或贴纸一样弹入；强调使用短促 Punch；循环动画保持轻微呼吸感。

### 4.2 大厅结构

大厅只回答“现在最值得做什么”，不把所有系统入口同权堆叠。

- 顶栏：玩家等级、鱼干、稀有资源和必要状态。
- 故事主卡：当前章节、今日目标、进度和唯一主 CTA。
- 伙伴角：当前同行伙伴、羁绊提示和一次轻互动。
- 营地远景：建筑修复状态直接反映在背景中。
- 底部导航：营地、任务、出发、图鉴、商店/设置等稳定入口。
- 面板：使用统一全屏覆盖或 Sheet，通过集中路由控制开关和返回行为。

### 4.3 局内 HUD

- 顶部左侧显示距离、分数和连击，顶部右侧显示鱼干、生命与关键资源。
- 下方只在需要时出现伙伴状态、道具持续时间和动作提示。
- Boss 激活时弱化非关键统计，突出生命、阶段、招式与反制提示。
- 中央和下半屏禁止持续性大面积装饰，保证障碍与预警可读。
- HUD 值只有变化时更新，静态与动态元素分离 Canvas，避免不必要重建。

### 4.4 结算

结算采用“旅程册新页”结构：

- 第一层展示本局结果、距离、分数、鱼干和最佳对比。
- 第二层展示死因复盘或胜利亮点，以及一条可执行建议。
- 第三层展示任务推进、新图鉴发现、伙伴羁绊和营地可升级项。
- 提供“再来一局”和“回营地”两个清晰行动；重新开始保持短链路。

## 5. 第二阶段：局内玩法深度

### 5.1 路线事件

在现有片段系统之上加入可配置的路线事件。事件必须提供明确读图、风险和结果，不能仅是随机弹窗。

首批事件类型：

- 安全路线与高收益路线岔路。
- 伙伴救援或护送片段。
- 宝箱、遗物或故事残页发现。
- 暴风雪、流星、极光共鸣等世界事件。
- Boss 前追逐、主题试炼和胜利奖励段。
- 达成条件后可提前撤离并保存部分收益的抉择节点。

### 5.2 局内轻构筑

关键里程碑或事件后提供三选一强化。强化改变道具和动作之间的组合关系，不只增加持续时间。

强化按四类组织：

- 移动：跳跃、滑铲、换道、冲刺与空中控制。
- 收集：磁力、鱼干连线、奖励倍率与稀有发现。
- 防护：护盾、完美闪避收益、受击保护与第二次机会。
- 伙伴：主动救援、协同收集、主题克制和羁绊触发。

单局强化数量设上限，避免无限叠加和 HUD 过载。所有强化在结算时清除，永久成长只解锁选择池或轻量起始优势。

### 5.3 技巧评分

技巧评分由明确事件驱动：完美闪避、连续换道、空中收集、无伤片段、危险路线完成和 Boss 反制。技巧链提供即时分数与短时倍率，但不取代距离和生存核心。

连击中断原因必须可解释，HUD 只在连击升级、即将中断或结算亮点时强化显示。

### 5.4 六主题 Boss

每个 Boss 必须具备独立剪影、主题色、招式池、反制窗口、阶段变化和专属战利品。攻击节奏仍使用 `Windup -> Telegraph -> Strike -> Recovery`。

伤害权威保持为现有链路：

`BossSystem.CheckPatternHit -> RunnerHitResolver.IsBossPatternHit -> IsPatternDangerous`

视觉、音频、震屏和粒子从同一攻击上下文读取，但不能增加额外碰撞体或独立伤害计时器。特效继续通过 `BossPatternFxPool` 租用和归还，保持容量上限与瞬时对象预算。

## 6. 第三阶段：长期成长

### 6.1 营地重建

营地由一组具有清晰前置条件和可见状态的建筑节点组成。升级同时带来三类反馈：场景外观变化、系统功能解锁和一段角色/世界故事。

首批建筑职责：

- 篝火：每日建议、连续游玩奖励和故事推进。
- 工坊：局前补给与可解锁强化池。
- 伙伴屋：同行伙伴、羁绊与专属任务。
- 图书帐篷：Boss、事件、遗物和故事残页图鉴。
- 瞭望台：主题选择、挑战纪录和下一威胁预告。

### 6.2 伙伴羁绊

伙伴不是纯数值宠物。每位伙伴包含：

- 一项易理解的局内被动。
- 一项有冷却或条件的主动救援。
- 一组专属任务和营地互动。
- 通过共同冒险推进的羁绊等级。
- 在特定主题、事件或 Boss 中出现的差异化对白与帮助。

羁绊升级优先解锁选择和故事，其次数值增益保持克制，避免形成唯一最优伙伴。

### 6.3 图鉴发现

图鉴按主题组织 Boss、事件、伙伴、遗物和故事残页。未知项目显示可理解的线索；新发现从结算进入图鉴，并支持直接跳转到相关主题或任务。

图鉴不以纯列表作为最终形态，而以可翻阅的章节页呈现收集关系和世界变化。

### 6.4 统一目标系统

每日任务、主题里程碑、成就和本地挑战纪录共享统一进度事件与领奖状态。大厅只显示当前最相关的一项建议，其余内容进入任务面板。

## 7. 技术架构

### 7.1 表现层

- 继续使用 uGUI、TextMeshPro、`UiBuilder` 和集中式 `UiTheme`。
- 扩展主题令牌，统一颜色、字体、间距、圆角、阴影、图标和动效时长。
- 将大厅拆为背景、顶栏、故事主卡、伙伴角、底部导航和面板路由等职责明确的组件。
- 公共组件只负责呈现和交互回调，不直接读取或写入复杂存档。

### 7.2 会话与玩法层

- `RunnerGameController` 继续编排单局流程，但路线事件、强化选择和技巧评分分别由独立模块维护状态。
- 模块通过明确事件或只读快照把数据交给 HUD、音频和特效。
- 新模块不得绕过现有碰撞、受击、Boss 命中和会话结算权威。

### 7.3 结算与成长层

单局结束生成统一旅程结果，其中包含基础成绩、技巧统计、事件结果、Boss 结果、发现物和任务事件。保存事务以该结果为输入，依次推进任务、营地、伙伴和图鉴，再刷新大厅视图模型。

存档增加显式版本和迁移入口。永久数据与单局临时数据分离，避免退出或重开后残留强化状态。

### 7.4 内容配置

六主题内容通过配置或目录表定义以下字段：

- 视觉与音频资源。
- 片段和路线事件池。
- 道具与强化偏好。
- Boss 定义与战利品。
- 遗物、故事残页和伙伴关联。

配置缺少可选资源时使用稳定回退；缺少会破坏规则的必填字段时在开发验证中明确失败。

## 8. 数据流

主数据流如下：

`局前配置 -> 跑酷会话 -> 路线/强化/Boss 事件 -> 统一旅程结果 -> 存档事务 -> 营地视图模型刷新`

界面层只能通过命令发起用户操作，并通过视图模型或只读快照刷新。特效和音频订阅玩法事件，不反向控制规则。

## 9. 异常与降级

- 字体、图标、贴图或音频缺失时使用内置回退，页面必须保持可操作。
- 存档读取失败时保留原数据的恢复副本，并使用安全默认值启动；不得静默覆盖唯一副本。
- 未解锁或暂不可用内容显示真实状态和解锁条件，不伪造零值或假进度。
- 特效池耗尽时减少装饰反馈，不阻塞输入、攻击阶段和命中判定。
- 配置不完整时在编辑器/静态验证阶段给出包含主题与字段名的诊断。
- 面板重复打开、返回或场景切换必须幂等，避免重复订阅和多次保存。

## 10. 验收与测试

### 10.1 自动验证

- 为路线选择、强化组合、技巧链、旅程结算、存档迁移和成长推进补充纯逻辑或 EditMode 测试。
- 扩展 `tools/VerifyUiArtP0.ps1` 或增加分阶段静态验证器，检查 UI 令牌、Boss 命中边界、池容量、资源引用和关键命名契约。
- 每阶段执行静态验证、C# 可用的编译检查、资源完整性检查和 `git diff --check`。

### 10.2 运行时流程

Unity 许可证可用时至少验证以下流程：

1. 大厅启动、面板开关和出发准备。
2. 普通跑酷、路线事件、强化选择和技巧链。
3. Boss 预警、完整招式、受击、反制、胜利与奖励段。
4. 死亡结算、再来一局和返回营地。
5. 营地升级、伙伴变化、图鉴发现和任务领奖。
6. 退出重进后的存档恢复和旧存档迁移。

### 10.3 视觉与性能

- 对大厅、普通跑酷、Boss、结算和营地成长状态保留关键截图。
- 横屏 16:9 下检查安全区、文字截断和中央/下半屏遮挡。
- Android Medium 档重点观察帧率、GC、Canvas 重建、SetPass、粒子和对象池峰值。
- 视觉效果按质量档位降级，降级不能改变玩法判定。

若本机 Unity 许可证仍不可用，只能将结果报告为静态验证通过；不能声称已经完成 Unity 编译、运行时或实机验证。

## 11. 分阶段交付

### 阶段一：童话视觉基础

交付设计令牌、公共组件、大厅、HUD、结算和主要面板统一。该阶段结束时，即使不依赖后续玩法，游戏也应具有完整且一致的品牌体验。

### 阶段二：局内玩法深度

交付路线事件、局内强化、技巧评分和六主题 Boss 深化。该阶段结束时，重复游玩应产生可感知的路线和构筑差异。

### 阶段三：长期成长

交付营地重建、伙伴羁绊、图鉴发现和统一目标反馈。该阶段结束时，每局结果都应至少推进一个清晰的短期或长期目标。

每阶段使用独立实施计划和验收清单。后续阶段只能依赖前一阶段公开接口，不直接依赖其内部实现。
