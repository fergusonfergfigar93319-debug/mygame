# 玩家旅程体验审查与缺陷修复设计

日期：2026-07-16

项目：企鹅快跑（PenguinRun）

目标平台：Android 横屏优先

## 目标

对当前项目进行一次完整、可复现的玩家体验审查，并修复会影响新玩家首局理解、老玩家持续复玩或 Android 横屏操作的缺陷。审查覆盖从启动到成长回流的完整链路，而不是只检查单个页面或已存在的静态验证。

本轮允许调整页面流程、教学时机、HUD、输入容错、低风险难度参数和反馈层级，但不重做核心架构，不引入联网、角色解锁或新的大型玩法系统。

## 玩家旅程范围

审查按以下八段执行：

1. 启动与首页：首个可操作时间、主 CTA、活动信息、资源信息和页面返回路径。
2. 模式与难度：Story、Endless、Daily 的区别、难度选择、取消和重复点击行为。
3. 首局教学：换道、跳跃、滑铲、道具和首个主题机关的教学顺序与信息量。
4. 基础跑酷：障碍预判、碰撞公平性、手势容错、道具反馈和低帧率下的输入响应。
5. 主题机关与 Boss：状态互斥、预警可读性、取消清理、难度突变和画面遮挡。
6. 暂停与中断：暂停/恢复、Android 返回键、应用失焦、重复恢复和时间缩放状态。
7. 失败与结算：死亡、完成、重试、返回大厅、单次奖励提交和结果信息层级。
8. 成长回流：主题精通、旅途契约、任务、营地建议、存档刷新和下一步行动提示。

新玩家与老玩家体验同权：首局必须清楚、可恢复；复玩必须避免重复提示、节奏停滞、无意义等待和奖励反馈缺失。

## 审查方法

### 证据优先

每个问题必须记录：

- 可重复的操作步骤；
- 预期行为与实际行为；
- 日志、状态或截图证据；
- 产生问题的代码路径和根因；
- 严重等级与修复决定。

不因主观审美或一次偶发现象直接修改平衡。无法稳定复现的问题先补充观测信息，确认边界后再决定是否修复。

### 问题分级

- P0：崩溃、卡死、存档损坏、奖励重复/丢失、无法继续游戏。本轮必须修复。
- P1：关键操作失效、不可恢复状态、碰撞明显不公平、主要 UI 被遮挡、Android 横屏无法完成操作。本轮必须修复。
- P2：可复现的信息过载、节奏断层、反馈缺失、视觉噪音或高频误操作。仅在根因明确且改动风险可控时修复。
- P3：纯偏好或需要大规模重构的改进。记录到报告，不在本轮扩展。

## 技术架构

### Editor 玩家旅程审查器

新增 Editor-only 审查入口，驱动真实场景和真实 UI 入口，收集运行时错误与关键状态。它应覆盖首页启动、开局、暂停恢复、失败/结算和返回大厅，不以只运行首页若干秒的烟测替代完整旅程。

审查器优先通过现有 Button 事件、场景入口和运行时公共/内部接口驱动流程。测试代码不进入 Android 正式运行程序集；除非缺少必要观测能力，不增加生产环境专用测试开关。确需增加时，只允许只读状态快照，不允许测试直接改写奖励、碰撞或存档结果。

### 状态与边界观测

审查器记录以下边界：

- 页面路由前后活动页面数量；
- RunSession 模式、主题、种子与难度；
- 运行状态、暂停状态、`Time.timeScale` 和应用焦点恢复；
- 主题机关、路线事件和 Boss 的互斥状态；
- 失败/完成后成长事务和 `PlayerSave.Flush` 次数；
- 结算、重试和返回大厅是否产生重复回调；
- HUD、弹层和安全区在 1920×1080、2560×1080、1280×720 下的边界。

### 视觉证据

使用 Unity 实际渲染输出首页、跑酷 HUD、主题机关/Boss 预警和结算页截图。前后对比只用于验证层级、可读性、遮挡与安全区，不以重新设计美术风格为目标。

## 修复边界

允许修改：

- 输入去抖、触摸阈值、暂停/失焦恢复和重复操作保护；
- 页面路由、弹层关闭、状态清理和返回路径；
- 教学出现条件、提示优先级、HUD 安全区和关键反馈；
- 有复现证据支持的节奏、容错和难度参数；
- Editor 自动化、回归断言、截图和审查报告。

保持不变：

- 障碍命中仍由 `ObstacleColliderSpec`、`CollisionSystem` 和既有命中解析层决定；
- 奖励与持久化仍由 `GrowthTransaction`、`RunOutcomeRouter` 和单次存档刷新负责；
- 视觉预制体不新增伤害、拾取或奖励权威；
- Boss、主题机关和路线事件继续遵守现有调度互斥关系；
- 不为本轮审查引入联网、角色系统或新的内容生产管线。

## 缺陷修复流程

对每个确认问题依次执行：

1. 读取完整错误或状态证据并稳定复现；
2. 追踪数据流，确认根因而非表面症状；
3. 添加最小失败回归测试并观察预期失败；
4. 只实现满足该测试的最小修复；
5. 运行局部测试、相邻系统回归和完整玩家旅程；
6. 在审查报告中记录修复、验证和剩余风险。

不同根因不合并为一次大改。连续三次假设失败时停止补丁叠加，重新评估系统边界。

## 错误与恢复策略

- UI 重复点击必须幂等或在转换期间禁用，不能重复加载场景或重复结算。
- 暂停、失焦和系统返回必须进入明确状态；恢复后 `Time.timeScale`、输入和音频状态一致。
- 主题机关或视觉资产缺失时恢复普通片段，不保留移动修饰器；关键签名资产缺失必须产生可诊断记录。
- 失败或完成后的成长事务最多提交一次；重试创建新的运行会话，不复用已结束会话的临时状态。
- 审查器自身超时或无法驱动某一步时输出明确失败点，不把未覆盖步骤报告为通过。

## 验证策略

### 自动验证

- 新增完整旅程 Editor 运行测试及针对每个修复的回归断言；
- 保留并扩展现有 UI 布局、主题机关、资源和运行时烟测；
- 运行七道 PowerShell 静态门禁；
- 运行主题机关 900 秒 × 60Hz 耐久验证；
- 运行 Unity 编译、玩家旅程、UI 布局、资源和主题机关验证；
- 生产运行时或 UI 发生改变时，必须执行 Android APK 构建前置检查并生成、验证新的 v2 签名测试 APK；若仅受外部 SDK/仓库状态阻塞，交付报告必须记录日志证据和已完成的本地验证。

### Android 横屏重点

- 16:9、20:9 和 1280×720 横屏构图不越过安全区；
- 主 CTA、暂停、恢复、重试和返回按钮在触摸环境可完成；
- Android 返回键不会跳过保存、重复关闭页面或直接留下不可恢复状态；
- 应用失焦/恢复不会让游戏在后台继续、永久停留暂停或遗留输入；
- 低帧率模拟下关键输入窗口和状态转换仍保持一致。

## 交付物

- 玩家旅程审查器与回归测试；
- 已确认 P0/P1 及低风险 P2 的修复；
- 首页、HUD、关键玩法和结算页的前后视觉证据；
- `docs/PLAYER_EXPERIENCE_AUDIT.md`，记录问题、严重度、根因、修复、验证和未处理项；
- 完整验证结果及 Android 构建状态。

## 完成标准

- 八段玩家旅程均有自动或明确的人工证据，不存在“未执行但报告通过”的步骤；
- 所有发现的 P0/P1 已有失败测试、最小修复和通过证据；
- 已处理 P2 有可重复证据，未处理 P2/P3 有清晰取舍；
- 首页到回大厅的主流程无错误、无重复结算、无不可恢复状态；
- Android 横屏关键操作、安全区、返回键和失焦恢复符合预期；
- 静态门禁、Unity 玩家旅程、布局、资源、主题机关和耐久验证全部通过；
- 工作区不包含未解释的生成物或无关修改。
